How it works

1
Invent a language.
Write code the way you imagine code should look. Any syntax. Any file extension. There are no rules and no errors.
2
Write down its rules.
Tell the compiler what your symbols and blocks mean — in Language Rules. It then follows your definitions instead of guessing at them.
3
Press Run.
Claude Code reads your imagination like a compiler reads source — and builds a real website from it.
4
Watch it exist.
A live preview opens right here in the IDE. Change your language, run again, dream bigger.
“there are no syntax errors in imagination.” — the compiler

Language Rules

Your language, defined by you. The compiler reads this before your source — so where you say what something means, it stops guessing and follows you.

Language Name

What you call the language you invented. Optional — but it makes the spec read like a spec.

How Your Language Works

A few sentences on the shape of it: what indentation does, how structure is expressed, what kind of thing a program describes. Write it as if explaining it to someone who has to implement it.

Syntax Glossary

The heart of it. Each row binds one construct to one meaning — the compiler treats these as law, above its own reading of what the symbol looks like it should mean.

when the source says… …the compiler must do this

Worked Examples

Optional, and unreasonably effective: a snippet of your language plus what it must compile to. The compiler treats each one as a test case it has to match.

Start from a shape

Templates for the three languages people invent most. They fill the fields — nothing is sent anywhere.

Read my language for me

Let the compiler read your workspace and propose a glossary. You review every line before anything is saved.

What the compiler reads

The exact text prepended to every build, rendered by the same code that builds the prompt.
